# Validate Project Documentation

Keep active documentation synchronized with the implementation and repository configuration.

## Workflow

1. Inspect the complete change scope:
   - `git status --short`
   - `git diff --name-only`
   - `git diff --cached --name-only`
   - Compare the branch with `main` when validating a PR.
2. Map implementation changes to documentation:
   - `packages/core/src/**`: update `packages/core/README.md`, public API tables, examples,
     Storybook stories, and the root README when behavior or usage changes.
   - `packages/shadcn/**`: update `packages/shadcn/README.md` and registry examples.
   - `apps/demo/**`: update demo links, routes, persistence examples, and GitHub Pages paths.
   - `.github/workflows/**`, package metadata, or repository renames: update release instructions,
     canonical URLs, npm metadata, Pages configuration, and `AGENTS.md`.
   - Version changes generated by Changesets only require changelogs; do not invent API docs.
3. Preserve historical records:
   - Do not rewrite `CHANGELOG.md` entries or `openspec/changes/archive/**` solely to modernize
     old URLs or behavior.
4. Run the deterministic gate:
   - `pnpm docs:check`
5. Review the resulting diff and report:
   - documentation updated;
   - documentation intentionally unchanged and why;
   - any external configuration still requiring verification.

## Repository invariants

- Canonical repository: `https://github.com/deandrenn2/dock-buttons`
- Canonical demo: `https://deandrenn2.github.io/dock-buttons/`
- npm Trusted Publisher for both public packages:
  - owner: `deandrenn2`
  - repository: `dock-buttons`
  - workflow: `release.yml`
- Public `ButtonDock` documentation must cover `layout`, `align`, and `sessionStorageKey`.
- Active documentation must not reference the former `deandrenn2/dock` repository or
  `deandrenn2.github.io/dock/` demo.

## Release and rename checks

When the repository name or release workflow changes:

1. Update each publishable package's `repository.url` and `homepage`.
2. Update README badges, clone commands, demo links, and contributor links.
3. Update Vite's production base and the GitHub Pages SPA fallback.
4. Verify npm Trusted Publishing separately for every package. The local validator cannot read
   npm account settings.
5. Re-run Release only after the npm publisher claims match the canonical repository and workflow.
